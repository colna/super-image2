# SuperImage2 — 实施任务拆解

> 基于 PRD、交互设计、技术架构三份文档，将 MVP 实施拆解为 6 个 Phase、33 个 Task。
> 每个 Task 粒度控制在可独立验证、单次提交的范围内。

---

## Phase 1: 项目脚手架

> 目标：从零搭建 Turborepo monorepo，两个 app 能 `pnpm dev` 跑起来，空白页面可访问。

### Task 1.1 — 初始化 Turborepo + pnpm workspace

- 初始化根 `package.json`（`packageManager: pnpm@9.15.0`）
- 创建 `pnpm-workspace.yaml`（`apps/*`, `packages/*`）
- 创建 `turbo.json`（dev / build / lint / test / type-check 任务定义）
- 配置 `.gitignore`（合并现有 + `node_modules`、`.next`、`.turbo` 等）
- 配置 `.env.example`

**验证**：`pnpm install` 成功，`turbo --version` 可用。

### Task 1.2 — 创建 packages/typescript-config

- `base.json`：strict 模式，target ES2022
- `nextjs.json`：继承 base，加 Next.js 专用 JSX/plugin 配置

**验证**：JSON 语法无误。

### Task 1.3 — 创建 packages/eslint-config

- `base.js`：TypeScript + import 排序规则
- `next.js`：继承 base + `eslint-config-next`
- `package.json` 声明依赖

**验证**：`pnpm lint` 在根目录不报错（此时无源文件）。

### Task 1.4 — 创建 packages/utils

- `src/cn.ts`：`clsx` + `tailwind-merge` 封装
- `src/crypto.ts`：Web Crypto API 加密/解密 API Key
- `src/storage.ts`：localStorage 类型安全读写
- `src/types.ts`：共享类型定义（Session, Message, ImageResult, GenerateParams, ProviderConfig, ImageProvider）
- `src/index.ts`：统一导出
- `package.json` + `tsconfig.json`

**验证**：`tsc --noEmit` 通过。

### Task 1.5 — 创建 packages/ui

- 初始化 `package.json`、`tsconfig.json`
- 配置共享 Tailwind preset（色彩体系、字体、圆角、间距 — 按交互设计文档）
- 创建基础组件骨架：`button.tsx`、`input.tsx`、`skeleton.tsx`、`index.ts`
- 安装 Radix UI 基础包（`@radix-ui/react-dialog`、`@radix-ui/react-dropdown-menu`、`@radix-ui/react-tooltip`）

**验证**：`tsc --noEmit` 通过，Tailwind preset 可被 apps 引用。

### Task 1.6 — 创建 apps/web（Next.js 骨架）

- `npx create-next-app` 或手动初始化：App Router + TypeScript + Tailwind
- `app/layout.tsx`：根布局（字体加载 Inter + Noto Sans SC）
- `app/page.tsx`：临时首页（显示 "SuperImage" 文字即可）
- 配置 `next.config.ts`、`tailwind.config.ts`（引用 packages/ui preset）
- `tsconfig.json` 继承 `packages/typescript-config/nextjs.json`
- `package.json` 声明对 `@super-image/ui`、`@super-image/utils` 的依赖

**验证**：`pnpm dev:web` 启动，浏览器访问 `localhost:3000` 看到页面。

### Task 1.7 — 创建 apps/home（Next.js 骨架）

- 同 Task 1.6 结构，独立 app
- `app/page.tsx`：临时首页（显示 "SuperImage — AI 图片生成" 文字）
- 共享 Tailwind preset + 字体配置

**验证**：`pnpm dev:home` 启动，浏览器访问 `localhost:3001` 看到页面。

### Task 1.8 — 整体验证 + 首次提交

- `pnpm dev` 同时启动两个 app
- `pnpm build` 全量构建成功
- `pnpm lint` 通过
- 提交代码：`feat: init turborepo monorepo with web and home apps`

**验证**：CI 三件套（dev / build / lint）全部绿色。

## Phase 2: 数据层 + Provider 系统

> 目标：Settings 可配置 API Key，Provider 系统可扩展，IndexedDB 持久化层就绪。

### Task 2.1 — IndexedDB 持久化层（Dexie.js）

- `apps/web/lib/db.ts`：定义 SuperImageDB（sessions / messages / imageStore 三张表）
- 索引设计：sessions 按 updatedAt，messages 按 `[sessionId+createdAt]` 复合索引，imageStore 按 messageId
- imageStore 存储原始 PNG Blob（**不压缩**），字段：`id`, `blob`, `messageId`, `createdAt`
- 封装 CRUD helper：`addSession`、`getSession`、`updateSession`、`deleteSession`、`getMessagesBySession`、`addMessage`
- 封装图片 helper：`saveImage(id, blob, messageId)` 存储原始 Blob、`getImage(id)` 读取 Blob、`getImagesByMessage(messageId)` 按消息查询

**验证**：编写简单测试脚本，在浏览器 DevTools IndexedDB 面板确认表和索引创建成功。

### Task 2.2 — Zustand Stores

- `stores/settings-store.ts`：Provider 配置 + persist 中间件（存 localStorage）
- `stores/session-store.ts`：会话列表 + 当前活跃会话 ID，与 Dexie.js 联动
- `stores/chat-store.ts`：当前会话的消息列表 + 生成状态 + 取消能力
- `stores/ui-store.ts`：侧边栏折叠状态、Settings 面板开关

**验证**：`tsc --noEmit` 通过，store 类型完整。

### Task 2.3 — Provider 系统 + OpenAI 实现

- `providers/types.ts`：`ImageProvider` 接口定义（含 `generate` 和可选 `edit` 方法）
- `providers/openai.ts`：OpenAI Provider 实现
  - `generate()`：调用 `/api/generate`（对应 OpenAI `/v1/images/generations`）
  - `edit()`：调用 `/api/edit`（对应 OpenAI `/v1/images/edits`）
  - 默认模型：`gpt-image-2`（首要支持目标）
  - 同时支持 `dall-e-3` 等其他模型
- `providers/registry.ts`：Provider 注册表，`getProvider()` / `listProviders()`

**验证**：`tsc --noEmit` 通过，openaiProvider 对象结构完整。

### Task 2.4 — API Route Handlers

- `app/api/generate/route.ts`：图片生成代理（Edge Runtime，Zod 校验，OpenAI SDK 调用，错误映射）
- `app/api/edit/route.ts`：图片编辑代理（接收 image + prompt，调用 OpenAI `/v1/images/edits`）
- `app/api/test-connection/route.ts`：连通性测试（轻量请求验证 API Key 有效性）
- 使用 `.env.local` 中的测试 Key 验证端到端链路（gpt-image-2，谨慎调用）

**验证**：`curl` 手动测试三个端点，返回预期 JSON 结构。

## Phase 4: 对话核心（Chat）

> 目标：完整的文字生图对话链路——输入 prompt → 调用 API → 展示图片。

### Task 4.1 — 页面布局骨架

- `app/chat/page.tsx` + `app/chat/[id]/page.tsx`：路由结构
- `components/chat-layout.tsx`：三区域布局（TopBar + Sidebar + ChatArea）
- TopBar：汉堡菜单 + "SuperImage" 标题 + Settings 图标
- 侧边栏占位（280px，可折叠）
- 对话区占位（消息流 + 输入框区域）

**验证**：访问 `/chat` 看到三区域布局，侧边栏可折叠/展开。

### Task 4.2 — 输入框组件

- `components/chat-input.tsx`：多行文本输入
- Enter 发送、Shift+Enter 换行、空输入抖动
- 自动扩展高度（60px → 最大 160px）
- 输入框上方快捷参数条：尺寸/质量/数量下拉选择
- 生成中状态：输入框禁用 + "生成中..." placeholder
- 发送按钮状态：空输入灰色 → 有内容黑色

**验证**：输入文字 → Enter 发送 → 触发回调 → 输入框清空。

### Task 4.3 — 消息流组件

- `components/message-list.tsx`：消息列表，自动滚动到底部
- `components/user-message.tsx`：用户气泡（右对齐，深色背景，白色文字）
- `components/ai-message.tsx`：AI 气泡（左对齐，白色背景，含图片区域）
- 时间戳显示

**验证**：手动添加测试消息，用户消息右对齐、AI 消息左对齐，样式符合设计稿。

### Task 4.4 — 图片生成完整链路

- 输入框发送 → `chat-store.sendMessage()` → 写入用户消息到 DB + 消息流
- 创建 pending AI 消息 → 调用 Provider `generate()` → 通过 Route Handler 调用 OpenAI
- API 请求使用 `response_format: "b64_json"` 获取原始 PNG base64 数据（**不压缩**）
- 成功：base64 解码为 Blob → 存入 IndexedDB imageStore → 生成 Object URL → 更新消息状态为 done
- 失败：更新为 error，展示错误信息
- 取消：AbortController 中断请求
- 组件卸载时 `URL.revokeObjectURL()` 释放内存

**验证**：输入 prompt → 看到骨架屏 → 图片生成成功展示。**端到端链路跑通。**

### Task 4.5 — 骨架屏 + 生成中状态

- `components/image-skeleton.tsx`：按图片尺寸展示灰色矩形，脉冲闪烁动画
- "正在生成..." 文字 + 取消按钮
- 图片加载完成后 fade-in 300ms 替换骨架屏

**验证**：发送 prompt 后看到骨架屏动画，图片淡入替换。

### Task 4.6 — 图片卡片组件

- `components/image-card.tsx`：图片展示 + hover 操作栏
- 列表中展示：使用 Blob URL + CSS `object-fit: cover` 缩放渲染，**源 Blob 不压缩**
- 操作栏：
  - 下载：从 IndexedDB 读取原始 Blob → `<a href={blobUrl} download="superimage-{id}.png">`，**输出原始 PNG**
  - 复制到剪贴板：`navigator.clipboard.write([new ClipboardItem({ 'image/png': blob })])`，**复制原始 PNG**
  - 编辑：基于此图原始 Blob 调用 `/v1/images/edits`
- "查看修改后的 prompt" 折叠/展开
- 多张图片时 2x2 网格布局

**验证**：图片 hover 出现操作栏，下载文件为原始 PNG（对比文件大小确认无压缩），复制功能正常。

### Task 4.7 — 错误状态处理

- 按交互设计文档实现 4 种错误状态组件：
  - 网络错误（红色左边框 + 重试按钮）
  - API Key 无效（去设置 + 重试）
  - 内容审核拦截（修改描述按钮 → 回填输入框）
  - 余额不足（前往充值外链）
- 错误出现在消息流中 AI 消息位置

**验证**：模拟各类错误，对应 UI 正确展示。

## Phase 5: 会话管理

> 目标：多会话 CRUD、侧边栏会话列表、搜索、空状态引导。

### Task 5.1 — 侧边栏会话列表

- `components/sidebar.tsx`：会话列表渲染
- 新建会话按钮（+ 图标）
- 每个条目：标题 + 最后消息预览（单行截断）+ 相对时间
- 当前会话高亮（左侧 2px 黑色竖条）
- hover 效果：背景变色 + 出现 ··· 更多按钮

**验证**：侧边栏展示多个会话条目，点击可切换。

### Task 5.2 — 会话 CRUD 对接

- 新建会话：创建 Session 记录 → 切换到新会话 → 对话区清空
- 切换会话：更新 activeSessionId → 加载该会话消息
- 删除会话：右键菜单 / ··· 菜单 → 二次确认弹窗 → 删除 Session + 关联 Messages
- 重命名会话：右键菜单 → inline 编辑 → 回车保存
- 自动标题：首条消息发送后，取前 20 字作为标题

**验证**：新建/切换/删除/重命名全流程跑通，刷新后数据不丢失。

### Task 5.3 — 会话搜索

- 侧边栏顶部搜索框
- 实时过滤：匹配标题和消息内容（从 IndexedDB 查询）
- 匹配项高亮关键词
- 空搜索结果提示

**验证**：输入关键词 → 列表实时过滤 → 清空恢复全部。

### Task 5.4 — 空状态与引导

- 未配置 API Key：居中引导卡片 + "配置 API Key" 按钮（打开 Settings）
- 已配置无会话：示例 prompt 卡片（4 个），点击填入输入框并自动创建新会话
- 输入框 placeholder：随机 prompt 灵感文字

**验证**：清空 IndexedDB，分别验证三种空状态展示正确。

### Task 5.5 — 路由 + URL 同步

- `/` 重定向到 `/chat`
- `/chat` 显示最近会话或空状态
- `/chat/[id]` 加载指定会话
- 新建会话时 `router.push('/chat/{newId}')`
- 切换会话时 `router.replace('/chat/{id}')`

**验证**：URL 随会话切换变化，刷新后恢复正确会话。

### Task 6.5 — 官网 Landing Page

**验证**：`pnpm dev:home` 启动，页面视觉完整，CTA 链接正确。
