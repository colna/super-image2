# SuperImage2 — 技术架构文档

## 1. 项目概述

SuperImage2 采用 **Turborepo + pnpm** 管理的 monorepo，包含两个独立应用：

| 应用   | 说明                         | 路径        |
| ------ | ---------------------------- | ----------- |
| `web`  | 文字生图对话平台（核心产品） | `apps/web`  |
| `home` | 官网 / Landing Page          | `apps/home` |

两个应用共享 UI 组件库和工具函数，最终均部署到 **Vercel 免费版**。

## 4. 关键架构决策

### 4.1 为什么需要 Server 端代理？

**问题**：浏览器直接调用 OpenAI API 会暴露 API Key（即使加密存储，请求中的 Authorization header 仍可在 DevTools 中看到）。

**方案**：Next.js Route Handler 作为代理层。

```
浏览器                    Vercel Server              OpenAI
  │                          │                        │
  │  POST /api/generate      │                        │
  │  body: {prompt, params}  │                        │
  │  header: x-api-key: xxx  │                        │
  │ ─────────────────────►   │                        │
  │                          │  POST /v1/images       │
  │                          │  Authorization: Bearer │
  │                          │ ────────────────────►  │
  │                          │                        │
  │                          │  ◄────── images ───── │
  │  ◄─── images ──────────  │                        │
```

**优势**：

- API Key 只在服务端出现，不暴露给浏览器网络面板
- 可在服务端做请求频率限制和参数校验
- 统一错误处理和日志
- Vercel 免费版 Serverless Function 够用（每月 100GB-hrs）

**客户端仍存储加密的 API Key**：每次请求通过自定义 header 传给服务端，服务端解密后调用 OpenAI。这样不同用户用自己的 Key，服务端无状态。

### 4.2 为什么用 Turborepo 而非单 app？

| 考量                         | 决策                                 |
| ---------------------------- | ------------------------------------ |
| 官网与产品是两个独立入口     | 独立部署，互不影响                   |
| 共享 UI 组件和 Tailwind 配置 | 避免重复代码                         |
| 构建缓存                     | Turborepo Remote Cache + Vercel 集成 |
| 未来扩展                     | 可加入更多 app（如文档站、管理后台） |

### 4.4 图片全链路无损策略

OpenAI 图片 URL 约 1 小时后过期，且 URL 传输经过 CDN 可能有压缩。因此采用 **base64 → Blob → IndexedDB** 策略，全程无损：

```
API 请求                     服务端/客户端                  浏览器存储 & 展示
─────────                    ──────────                    ─────────────────
response_format:             base64 PNG 原始数据            IndexedDB image-store
"b64_json"        →          解码为 Blob (image/png)   →   存储原始 Blob
                                                           │
                                                           ├─→ 列表缩略图: <img> + CSS object-fit
                                                           │   (浏览器缩放渲染，源数据不压缩)
                                                           │
                                                           ├─→ Lightbox 预览: 原始尺寸 Blob URL
                                                           │   (无缩放，100% 原图)
                                                           │
                                                           └─→ 下载: Blob → <a download>
                                                               (原始 PNG 文件，无任何压缩)
```

**关键实现要点**：

1. **API 请求**：`response_format: "b64_json"`，获取 base64 编码的原始 PNG
2. **解码存储**：`atob()` → `Uint8Array` → `new Blob([...], { type: 'image/png' })` → 存入 IndexedDB
3. **展示**：通过 `URL.createObjectURL(blob)` 生成临时 URL，组件卸载时 `URL.revokeObjectURL()` 释放
4. **列表缩略图**：同一 Blob URL，CSS 控制尺寸（`object-fit: cover`），浏览器负责缩放渲染，不生成额外压缩副本
5. **预览**：Lightbox 中使用原始 Blob URL，不限制 `width/height`，用户可看到 100% 原图
6. **下载**：直接从 IndexedDB 读取 Blob → `<a href={blobUrl} download="image.png">`，输出原始 PNG

**注意事项**：

- base64 数据量约为原始文件的 1.33 倍，1024×1024 PNG 约 2-4MB，存储时转为 Blob 恢复原始大小
- IndexedDB 存储上限因浏览器而异（Chrome 约为磁盘的 80%），正常使用不会触及
- 组件卸载时必须 `revokeObjectURL` 防止内存泄漏

### 5.2 Route Handlers（Server 端）

```typescript
// apps/web/app/api/generate/route.ts
import { NextRequest, NextResponse } from "next/server";
import OpenAI from "openai";
import { z } from "zod";

const schema = z.object({
  prompt: z.string().min(1).max(4000),
  model: z.string(),
  size: z.string(),
  quality: z.string(),
  n: z.number().min(1).max(4),
});

export async function POST(req: NextRequest) {
  // 1. 从 header 获取加密的 API Key，服务端解密
  const apiKey = req.headers.get("x-api-key");
  const baseUrl = req.headers.get("x-base-url") || "https://api.openai.com/v1";

  if (!apiKey) {
    return NextResponse.json(
      { error: { code: "missing_api_key", message: "API Key is required" } },
      { status: 401 },
    );
  }

  // 2. 校验请求体
  const body = schema.safeParse(await req.json());
  if (!body.success) {
    return NextResponse.json(
      { error: { code: "invalid_params", message: body.error.message } },
      { status: 400 },
    );
  }

  // 3. 调用 OpenAI
  const client = new OpenAI({ apiKey, baseURL: baseUrl });
  try {
    const response = await client.images.generate({
      model: body.data.model,
      prompt: body.data.prompt,
      size: body.data.size as any,
      quality: body.data.quality as any,
      n: body.data.n,
      response_format: "b64_json", // 原始 PNG base64，不压缩
    });

    return NextResponse.json({
      images: response.data.map((img) => ({
        b64_json: img.b64_json, // 原始 base64 PNG 数据
        revisedPrompt: img.revised_prompt,
      })),
    });
  } catch (err: any) {
    // 4. 错误映射
    const status = err.status || 500;
    const code = err.code || "generation_failed";
    const message = err.message || "Image generation failed";
    return NextResponse.json({ error: { code, message } }, { status });
  }
}
```

## 7. Vercel 部署方案

### 7.1 免费版限制与应对

| 限制                     | 额度          | 应对策略                                       |
| ------------------------ | ------------- | ---------------------------------------------- |
| Serverless Function 执行 | 100 GB-hrs/月 | 图片生成是转发请求，执行时间短                 |
| 带宽                     | 100 GB/月     | 图片通过 OpenAI URL 直接加载，不走 Vercel 带宽 |
| 构建时间                 | 6000 分钟/月  | Turborepo 缓存加速，增量构建                   |
| 项目数                   | 无限          | web 和 home 各一个 Vercel 项目                 |
| Serverless 超时          | 10s (Hobby)   | 图片生成可能超时，需处理（见下方）             |

### 7.2 Serverless 超时处理

Vercel 免费版 Serverless Function 最长 **10 秒**。DALL·E 3 生成通常 5-15 秒，可能超时。

**方案 A：客户端直调（推荐用于 MVP）**

对于自带 API Key 的个人工具，可以让浏览器直接调用 OpenAI API（Key 存在客户端）。Route Handler 仅用于连通性测试等轻量操作。

```typescript
// 客户端直调模式
const client = new OpenAI({
  apiKey: decryptedKey,
  baseURL: userBaseUrl,
  dangerouslyAllowBrowser: true, // 明确标记
});
```

**方案 B：Streaming Response**

使用 Edge Runtime 将超时上限提升到 30 秒：

```typescript
// apps/web/app/api/generate/route.ts
export const runtime = "edge"; // Edge Functions 在免费版有 30s 超时
```

**方案 C：轮询模式（后续迭代）**

提交生成任务 → 返回 taskId → 客户端轮询结果。适用于接入耗时更长的模型。
